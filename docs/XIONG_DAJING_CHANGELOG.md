## 四、开发日志（2026-11-09）

1. 底部导航改为“首页 / 健康问答 / 学说”；问学不再单独占一个标签，从学说页的“看学说 · 问学”卡片和首页进入，问学页有返回按钮。
2. 首页加两张入口卡“求诊（诊前问诊 · 情志自测）”“求学（看学说 · 问学）”。
3. 学说页问学卡：两个推荐问题和“进入问学 →”按钮，适用人群句“专供中医学习者与医师研习学说；个人健康问题请到医院面诊。”
4. 健康问答改为聊天式（`xiongChat.ts`、`XiongChatIntake.tsx`）：
   - 窗口头是“预问诊助手”，不用头像，配色用竹青，和问学区分开；下面有一条安全提示，急症拨打 120；
   - 分三部分：基本情况、中医问诊、情志自测；
   - 答题按钮整行、带编号；按下是浅竹青底，选中是浅底加粗框和勾，全程没有黑色；
   - 大组拆成小题；症状先在头面部图上点部位，只问点到的部位；
   - 跳过的题记为缺失，不记 0 分；量表缺题时报告标“未完成（已答 x/y）”；
   - 危险条目（SCL-90 第 15、59、63 题，呼吸困难、大便带有血丝、情绪躁狂）出现时，求助卡置顶，文案原样保留；
   - 最后生成四块就诊报告，可复制全文；
   - 全部在本机处理，不发给 AI。
5. 原表格版收成医生端小入口（演示），患者端只留“问答填写 / 量表测试”。
6. 熊老全站小动效（中医主调）：墨滴“正在输入”、淡墨晕开、印章式勾、卷轴展开、卡片如墨渐显；手机点按高亮用浅竹青；系统开启“减弱动态效果”时关闭。
7. 界面去掉“CRF 表、需求说明、数据库”字样。

## 六、待办方案（后续考虑）：让医生看到患者记录

现状：患者记录先存在患者自己的手机上；微信登录后，同步到患者本人在本平台的账户里。后台目前没有任何页面能看到这些记录。医生端小入口只能当演示用，医生看到的是自己手机上的记录。

| 方案 | 做法 | 前提 |
|---|---|---|
| A 患者出示报告 | 面诊时打开或复制就诊报告 | 现在可用 |
| B 报告码 | 患者端生成有有效期的二维码或短码，医生扫码看 | 服务器存报告、患者同意 |
| C 本平台医生后台 | 医生登录后，看授权给自己的患者记录 | 医生账号、授权绑定、权限、操作记录、隐私审查 |
| D 接医院或团队已有系统 | 报告推送到对方系统 | 对方提供接口并审批 |
| E 研究数据导出 | 医生端导出 CSV | 知情同意书 |

由本人和杨总、陈主任商定后再开发。
